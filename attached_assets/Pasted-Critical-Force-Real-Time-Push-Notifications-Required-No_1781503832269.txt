Critical: Force Real-Time Push Notifications (Required, Not Optional)
Current Problem:

Push notification permission is optional and shown too late
Buyers/sellers miss order requests and chat messages in real time
When a user leaves the platform, they get no notification at all

Required Changes:
1. Force notification permission on first login/register

Immediately after login or registration succeeds, before navigating anywhere, request browser notification permission
Show a full-screen overlay/modal explaining WHY notifications are needed: "Enable notifications to receive order requests, chat messages, and payment alerts in real time. Without this, you may miss trades."
Two buttons: "Enable Notifications" (primary, big) and "Maybe Later" (small, grey)
If user clicks "Maybe Later", show the same modal again on next login — never skip it permanently
If permission is denied by browser, show instructions on how to re-enable it in browser settings

2. Subscribe to push notifications immediately after permission granted

After permission is granted, immediately call the VAPID subscription endpoint
Save the push subscription to the database linked to the user's account
VAPID keys are already in .env as VAPID_PUBLIC_KEY and VAPID_PRIVATE_KEY

3. Trigger push notifications for these events (server-side)

Send a Web Push notification to ALL relevant subscribers when:

🛒 New order request → notify the AD OWNER (seller)
💬 New chat message → notify the OTHER PARTY in the order
✅ Payment marked as sent → notify the seller
🔓 Crypto released → notify the buyer
❌ Order cancelled → notify both parties
📋 KYC status changed (approved/rejected) → notify the user
🚨 Appeal/dispute raised → notify admin AND the other party

4. Push notification format

Each notification must include:
title: "Xendrx — [Event Name]"
body: "[Short description, e.g. 'Ali wants to buy 100 USDT from you']"
icon: "/icons/icon-192x192.png"
badge: "/icons/icon-96x96.png"
data: { url: "/orders/[orderId]" }  ← clicking opens the relevant page
5. Service Worker (sw.js) must handle background push

The existing sw.js must listen for push events
On receiving a push, show the notification using self.registration.showNotification()
On notificationclick, open or focus the relevant URL from event.notification.data.url

6. Notification for users NOT on the platform

Web Push works even when the browser tab is closed (as long as browser is running)
This is already supported by the VAPID setup — just make sure the service worker is properly registered and the push subscription is saved per-user in the database

7. Admin broadcast also sends push

When admin sends a broadcast, also send Web Push to all subscribed users (in addition to email/telegram)
