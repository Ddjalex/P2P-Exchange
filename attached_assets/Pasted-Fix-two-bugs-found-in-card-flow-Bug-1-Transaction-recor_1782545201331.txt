Fix two bugs found in card flow:
Bug 1 — Transaction recorded before StroWallet confirms:
Currently the code writes the transaction record BEFORE StroWallet responds. If StroWallet fails, the transaction is still recorded even though the wallet was refunded.
Fix in POST /api/cards/create AND POST /api/cards/fund:
typescript// WRONG — current order:
// 1. Deduct wallet
// 2. Write transaction record  ← too early!
// 3. Call StroWallet
// 4. If fails → refund wallet but transaction record stays

// CORRECT — new order:
// 1. Deduct wallet
// 2. Call StroWallet
// 3. If fails → refund wallet, DO NOT write transaction
// 4. If success → THEN write transaction record
Specifically fix:

Card creation fee transaction — only record AFTER StroWallet confirms success: true
Card fund transaction — only record AFTER StroWallet confirms success: true
Card withdraw transaction — only record AFTER StroWallet confirms success: true

Also clean up the duplicate card creation fee transactions for user 3:
sql-- Keep only the real one (the one that actually created the card)

The backend rejects amounts less than $1 but StroWallet requires minimum $2. Fix:
