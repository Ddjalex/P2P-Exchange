## Overview

Build a Keno casino game as a new, self-contained feature on the xendrx platform, placed in the app's bottom navigation near the existing "Card" button, labeled "Games." The game uses its own **separate Keno game wallet balance** — funded via a "Top Up" flow that moves money from the user's main xendrx wallet into their Keno game wallet, and (in Real mode) can be withdrawn back to the main wallet.

Color theme: **purple** as the primary accent throughout the Keno UI.

---

## 1. Demo Mode vs Real Mode

Before entering the game, the user chooses one of two modes:

**Demo Mode:**
- Uses a separate, non-real virtual balance (e.g., every user starts with a fixed demo balance like 10,000 virtual credits, can be reset)
- No connection to real money at all
- No Top Up needed (demo balance is pre-set/free)
- No Withdraw option available
- Clearly labeled "DEMO" throughout the UI so it's never confused with real play

**Real Mode:**
- Uses the real Keno game wallet balance (funded via Top Up, see below)
- Full Top Up and Withdraw options available
- All rounds logged as real-money transactions

## 2. Top Up Flow (Real Mode)

On the Keno game panel (or a wallet sub-screen within it), provide a "Top Up" button:

1. User selects a preset amount button: **$5, $20, $50, $100, $250, $500, $1000** — or enters a custom amount
2. Clicking "Top Up" prompts for the user's **account login password** (reuse the existing password-verification pattern already used for withdrawals elsewhere in the app — same bcrypt compare + rate limiting approach)
3. On password confirmation:
   - Check the user's **main xendrx wallet** has sufficient balance
   - If sufficient: atomically (within a database transaction with row locking) debit the main wallet and credit the Keno game wallet by the same amount
   - If insufficient: show a clear "Insufficient balance in main wallet" error, no changes made
4. Log this as a transaction (both in the main wallet's transaction history as a "Keno Top-Up" debit, and in a new Keno-specific transaction table as a credit)

## 3. Withdraw Flow (Real Mode only)

Provide a "Withdraw" button (only visible/enabled in Real mode):

1. User enters an amount up to their current Keno game wallet balance
2. Prompts for account login password (same verification pattern as Top Up)
3. On confirmation: atomically debit the Keno game wallet and credit the user's main xendrx wallet by the same amount
4. Log this as a transaction in both places (main wallet: "Keno Withdrawal" credit; Keno table: debit)

## 4. Game Rules & Math Engine

- Number pool: 1–80
- System draws 20 unique numbers per round (no replacement)
- Player selects 1–10 numbers ("spots")
- Compare player's picks against drawn numbers to count matches ("hits")
- Payout = Bet Amount x Multiplier(picks, hits), looked up from an **admin-configurable paytable**

**Randomness requirement:** Use a cryptographically secure random number generator (Node's built-in `crypto.randomInt()`), NOT `Math.random()`, to draw the 20 numbers. This is non-negotiable for fairness/security.

**Reference odds (hypergeometric distribution)** — use these to validate default paytable RTP:

| Picks | Hits | Probability |
|-------|------|-------------|
| 1 | 1 | 25.00% |
| 5 | 3 | 8.39% |
| 5 | 4 | 1.21% |
| 5 | 5 | 0.064% |
| 10 | 5 | 5.14% |
| 10 | 8 | 0.0135% |
| 10 | 10 | 0.00000112% |

## 5. Admin-Configurable Paytable & House Edge

The admin must be able to configure, per pick-count (1-10 spots), the payout multiplier for each possible hit count.

- Store in a new table `keno_paytable`: `picks`, `hits`, `multiplier` (numeric, e.g. `3.2000`)
- Seed sensible default values targeting roughly **80% RTP / 20% house edge**, using correct hypergeometric probabilities to calculate multipliers (show your calculation, don't just guess numbers)
- Admin panel must show the live-calculated RTP % per pick-count as multipliers are edited, before saving

## 6. Game Round Flow (Backend)

New route file `artifacts/api-server/src/routes/keno.ts`, endpoint `POST /api/games/keno/play`:

1. **Validate**: numbers are 1-80, no duplicates, count is 1-10, bet amount positive and within admin-configured min/max limits, and correct mode (demo vs real) is respected
2. **Atomic balance check + debit** from the appropriate wallet (Keno game wallet for real, demo balance for demo) using a database transaction with row-level locking (`SELECT ... FOR UPDATE`) — no simple read-then-write pattern
3. **Draw**: generate 20 unique random numbers using `crypto.randomInt()`
4. **Match**: count intersection between player picks and drawn numbers
5. **Payout**: look up multiplier, calculate payout, credit the appropriate balance atomically
6. **Log**: insert into `keno_rounds`: `id, user_id, mode (demo/real), picks, drawn_numbers, bet_amount, hit_count, multiplier, payout_amount, created_at`
7. Return full result: drawn numbers, hits, payout, new balance

## 7. Database Schema (new tables)

```sql
CREATE TABLE keno_wallets (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL UNIQUE REFERENCES users(id),
  real_balance NUMERIC(12,2) NOT NULL DEFAULT 0,
  demo_balance NUMERIC(12,2) NOT NULL DEFAULT 10000,
  updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE TABLE keno_transactions (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id),
  type TEXT NOT NULL,
  amount NUMERIC(12,2) NOT NULL,
  mode TEXT NOT NULL,
  balance_after NUMERIC(12,2) NOT NULL,
  created_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE TABLE keno_paytable (
  id SERIAL PRIMARY KEY,
  picks INTEGER NOT NULL,
  hits INTEGER NOT NULL,
  multiplier NUMERIC(10,4) NOT NULL DEFAULT 0,
  UNIQUE(picks, hits)
);

CREATE TABLE keno_rounds (
  id SERIAL PRIMARY KEY,
  user_id INTEGER NOT NULL REFERENCES users(id),
  mode TEXT NOT NULL,
  picks JSONB NOT NULL,
  drawn_numbers JSONB NOT NULL,
  bet_amount NUMERIC(12,2) NOT NULL,
  hit_count INTEGER NOT NULL,
  multiplier NUMERIC(10,4) NOT NULL,
  payout_amount NUMERIC(12,2) NOT NULL,
  created_at TIMESTAMP NOT NULL DEFAULT NOW()
);

CREATE TABLE keno_settings (
  key TEXT PRIMARY KEY,
  value TEXT NOT NULL,
  updated_at TIMESTAMP NOT NULL DEFAULT NOW()
);
-- settings: min_bet, max_bet, game_enabled, min_topup, max_topup
```
